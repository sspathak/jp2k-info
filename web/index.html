Architecture & Standard Reference

Understanding the JPEG 2000 Format (ISO/IEC 15444-1)

A comprehensive handbook on wavelets, multiresolution decomposition, progression orders, and EBCOT entropy coding.

🌊

1. Discrete Wavelet Transform (DWT) vs DCT

Unlike legacy JPEG which divides images into $8 \times 8$ blocks resulting in visible blocking artifacts at high compression, JPEG 2000 applies a full-frame Discrete Wavelet Transform.

  • Mallat Octave Decomposition: Recursively splits the lowest frequency subband into four frequency orientations:
    • LL: Low-pass horizontal & vertical (Approximation)
    • HL: High-pass horizontal, low-pass vertical (Vertical edges)
    • LH: Low-pass horizontal, high-pass vertical (Horizontal edges)
    • HH: High-pass horizontal & vertical (Diagonal textures)
  • Zero Blocking Artifacts: Energy is concentrated into wavelet coefficients across scales, producing smooth, natural degradation rather than grid squares.
⚖️

2. Lossless 5/3 vs Lossy 9/7 Wavelets

JPEG 2000 defines two standard wavelet filters specified in the COD marker segment:

  • Le Gall 5/3 (Reversible): Integer-to-integer filter. Used with the Reversible Component Transform (RCT). Guarantees mathematically bit-exact reconstruction with zero loss. Used in medical imaging, archiving, and remote sensing.
  • Daubechies CDF 9/7 (Irreversible): Floating-point filter. Used with the Irreversible Component Transform (ICT). Delivers exceptional compression efficiency and high visual SNR at low bitrates.
📈

3. Progression Orders & Scalability

JPEG 2000 organizes bitstream packets using 5 progression orders, enabling different extraction paradigms without re-encoding:

Order Name Optimal Use Case
LRCP Layer-Resolution-Component-Position Progressive quality / SNR streaming. Whole image appears blurry then sharpens.
RLCP Resolution-Layer-Component-Position Progressive resolution. Perfect for quick thumbnails and zoom tiers.
RPCL Resolution-Position-Component-Layer Spatial and resolution streaming. Commonly used in web GIS and map viewing.
PCRL Position-Component-Resolution-Layer Interactive spatial panning across large images.
CPRL Component-Position-Resolution-Layer Displays complete color channel before subsequent channels.
🧩

4. EBCOT & Fractional Bitplanes

EBCOT (Embedded Block Coding with Optimal Truncation) partitions each wavelet subband into small autonomous code-blocks (typically $64 \times 64$ or $32 \times 32$ pixels).

Each bitplane is encoded across 3 fractional passes using context-adaptive MQ arithmetic coding:

  1. Significance Propagation Pass: Encodes coefficients that are not yet significant but have significant neighbors.
  2. Magnitude Refinement Pass: Refines the bits of coefficients that became significant in previous bitplanes.
  3. Cleanup Pass: Encodes the remaining insignificant coefficients using run-length and context coding.
🛡️

5. The 6 Error-Resilience Modes

JPEG 2000 supports granular mode switches in the COD / COC marker to enhance speed or robustness over unreliable transmission channels:

  • 0x01 BYPASS (Lazy coding): Bypasses arithmetic coding during refinement passes, improving compression throughput by up to 50%.
  • 0x02 RESET: Resets arithmetic context probabilities to uniform at the boundary of each coding pass.
  • 0x04 TERMINATE: Forces termination of the arithmetic codeword at the end of every pass.
  • 0x08 CAUSAL: Restricts context modeling to scan lines above, preventing dependency across coding passes.
  • 0x10 PREDICTABLE: Inserts predictable termination patterns for bitstream error detection.
  • 0x20 SEGSYM: Inserts a special 4-symbol sequence (1010 = 0x0A) at bitplane pass ends to detect transmission corruption.
📦

6. JP2 Box Containers vs Raw J2K

JPEG 2000 files exist in two primary flavors:

  • JP2 Box Container (.jp2): Uses ISO base media box packaging (start signature jP\040\040). Stores color profiles (colr, ICC profiles), channel definitions (cdef), capture resolutions (resc), and XML metadata.
  • Raw J2K Codestream (.j2k, .jpc): Pure compressed bitstream starting with the SOC marker (0xFF4F). Contains zero file-level metadata overhead; used in streaming protocols, medical DICOM encapsulation, and video (DCI).
