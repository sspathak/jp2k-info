Discrete Wavelet Transform (DWT) vs Discrete Cosine Transform (DCT)

Legacy JPEG divides an image into fixed $8 \times 8$ blocks and applies the DCT independently to each block. At high compression, quantized high frequencies create severe blocking artifacts and edge discontinuities.

JPEG 2000 uses a continuous full-frame Discrete Wavelet Transform via the Mallat octave pyramid:

  • Energy Concentration: DWT concentrates image energy into subbands containing both spatial location and frequency orientation.
  • No Block Boundaries: Compression degradation manifests as gentle, smooth blurring across the image instead of harsh grid artifacts.
  • Native Multiresolution: Decoding just the lowest subband yields a pristine $1/2^N$ resolution thumbnail without decompressing full resolution data.

The 5 Progression Orders: Scalability in 4 Dimensions

In JPEG 2000, codestream packets represent an intersection of Layer (L), Resolution (R), Component (C), and Position/Precinct (P).

  • LRCP: Layer-Resolution-Component-Position. Ideal for web streaming where image quality sharpens progressively across the entire canvas.
  • RLCP: Resolution-Layer-Component-Position. Ideal for thumbnail generation and interactive zooming (loads lowest resolution scale first).
  • RPCL: Resolution-Position-Component-Layer. Ideal for geographic map servers (GIS) and large remote sensing imagery.
  • PCRL: Position-Component-Resolution-Layer. Optimized for raster display hardware and interactive panning.
  • CPRL: Component-Position-Resolution-Layer. Transmits entire primary channel (e.g. Luminance Y) before color components.

EBCOT (Embedded Block Coding with Optimal Truncation)

EBCOT processes wavelet subbands independently in small code-blocks (usually $64 \times 64$). Quantized transform coefficients are coded bitplane by bitplane from Most Significant Bit (MSB) to Least Significant Bit (LSB).

Each bitplane is traversed using three fractional coding passes to maximize Rate-Distortion optimization:

  1. Significance Propagation Pass (SPP): Evaluates insignificant samples whose 8 immediate neighbors have already become significant.
  2. Magnitude Refinement Pass (MRP): Refines the bits of samples that became significant in earlier bitplanes.
  3. Cleanup Pass (CP): Coded with context aggregation and run-length coding to process all remaining samples.

The 6 SPcod Arithmetic Mode Switches

Defined in the COD / COC marker segments, these flags fine-tune speed and noise resilience:

Flag Mask Mode Name Function & Encoding Effect
0x01 Selective Bypass (Lazy coding) Bypasses MQ arithmetic coding on magnitude refinement passes, passing raw bits directly. Up to 50% faster encoding.
0x02 Reset Context Probabilities Resets arithmetic context state machine to uniform probability at coding pass boundaries.
0x04 Pass Termination Terminates the arithmetic codeword at the conclusion of every individual coding pass.
0x08 Vertically Causal Context Limits context neighbors to current and previous scanlines, preventing cross-pass hardware dependencies.
0x10 Predictable Termination Inserts strict predictable termination patterns verified by decoders to detect bitstream corruption.
0x20 Segmentation Symbols Inserts a 4-symbol marker (1010 = 0x0A) after each bitplane to flag transmission errors.

JP2 Box Container vs Raw J2K Codestream

A JPEG 2000 file can be encapsulated as a standardized box container or formatted as raw codestream:

  • JP2 Box Container (.jp2): Formatted as nested LBox/TBox structures. Contains color ICC profiles (colr), metadata XML (xml ), channel definitions (cdef), capture resolutions (resc), and contiguous codestream (jp2c).
  • Raw J2K Codestream (.j2k, .jpc): Starts directly with Start of Codestream (SOC = 0xFF4F) delimiter. No container overhead; ideal for DICOM embedding, video streaming (Motion JPEG 2000 / DCI), and raw asset pipelines.

Libraries & Engines Powering JPEG2000 info

This application combines open-source C libraries with custom binary parsers to provide both server-grade and 100% offline browser inspection:

  • OpenJPEG v2.5.4 (libopenjp2): The official open-source C reference implementation maintained by the JPEG committee. Used on the backend and CLI to generate, validate, and decompress sample profiles into rasters (opj_decompress, opj_compress, opj_dump).
  • ClientJP2Parser (Browser Native JavaScript): Our custom, zero-dependency binary parser implemented in vanilla JavaScript using the native DataView and Uint8Array APIs. Reads and decodes every box and codestream marker segment directly inside the client's web browser, enabling true serverless deployment on GitHub Pages.
  • JPEG2000Parser (Python Backend & CLI): Pure-Python binary parsing engine for terminal dumps, JSON extraction, and Markdown reports without requiring native compilers or external Python packages.
  • Pixi Package Manager: Reproducible environment orchestrator providing pinned multi-platform binaries across macOS, Linux, and Windows via Conda-Forge.
